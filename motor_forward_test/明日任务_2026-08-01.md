## 总目标

1. 记录左右编码器脉冲和实际行驶距离，得到可靠的“脉冲/厘米”参数；
2. 调整编码器整圈停车距离，使小车完成一圈后稳定回到 A 点，停车偏差不超过 `2 cm`。

## 任务 1：记录编码器脉冲和距离

### 明日先执行：直线标定

先不跑整圈。构建并烧录独立直线标定固件：

```sh
make encoder-distance-calibration-test
./flash_xds110.sh --yes build/encoder_distance_calibration_test.out
```

固件上电后保持停车；摆好车辆并按下、释放 `PB7` 后，左右轮各累计到 `6000` 脉冲便短刹并自动停止。运行中再次按 `PB7` 可以中止。停车后量起点到车辆同一参考点的实际距离，并记录 OLED `ENC左/右` 或 CCS 中的：

```text
g_encoder_cal_left_count
g_encoder_cal_right_count
g_encoder_cal_completed
g_encoder_cal_timed_out
g_encoder_cal_aborted
```

有效结果必须满足 `g_encoder_cal_completed == 1`、
`g_encoder_cal_timed_out == 0` 且 `g_encoder_cal_aborted == 0`。

### 1.1 直线基础标定

- [ ] 在地面准确量出一段 `100 cm` 直线，标清起点和终点；
- [ ] 启动时让车轮编码器清零；
- [ ] 每次运行后，从 OLED 的 `ENC左轮/右轮` 页面或 CCS Expressions 读取：
  - `g_motorA_encoder_count`：左轮累计脉冲；
  - `g_motorB_encoder_count`：右轮累计脉冲；
- [ ] 每次同时记录车辆实际行驶距离，不要只记录程序设定距离；
- [ ] 至少重复 `3–5` 次，不用单次结果直接改参数。

计算公式：

```text
左轮脉冲/厘米 = |左轮累计脉冲| ÷ 实际距离(cm)
右轮脉冲/厘米 = |右轮累计脉冲| ÷ 实际距离(cm)
整车平均脉冲/厘米 =
    (|左轮累计脉冲| + |右轮累计脉冲|) ÷ 2 ÷ 实际距离(cm)
```

将多次测试的“整车平均脉冲/厘米”取平均，作为
`H_TRACK_LF04_ENCODER_COUNTS_PER_CM` 的候选值。

### 1.2 多方位复核

- [ ] 在相同直线反复测试，检查重复性；
- [ ] 分别在电池电量较足和运行一段时间后测试，观察脉冲换算是否变化；
- [ ] 完整跑圈时记录左右脉冲差，判断轮胎打滑、轮径差和弯道误差；
- [ ] 同时记录运行时间、停车航向和实际停车位置，便于区分“距离误差”和“航向误差”；
- [ ] 如果左右轮脉冲/厘米长期存在固定差异，分别保留左右轮标定值，不要只靠一个 PWM 偏置掩盖。

### 2026-07-31 首轮直线结果

前三次只有约数；随后两张 OLED 照片已确认短刹后的准确值：

```text
第 1 次：绝对距离 97.0 cm，左轮 6173，右轮 6072
第 2 次：绝对距离 96.5 cm，左轮 6298，右轮 6054

左轮合并标定 = (6173 + 6298) ÷ (97.0 + 96.5)
             ≈ 64.45 脉冲/cm
右轮合并标定 = (6072 + 6054) ÷ (97.0 + 96.5)
             ≈ 62.67 脉冲/cm
整车平均标定 ≈ 63.56 脉冲/cm
```

程序已分别保存左右轮标定值，不再假定两轮的脉冲/厘米相同。这里按队员给出的
“直线绝对距离” `97.0/96.5 cm` 计算；`92/94.5 cm` 作为黑线方向记录保留，
没有混入轮程换算。

- 两轮标定值相差约 `2.8%`，正式停车里程必须先把左右脉冲分别换算成距离再取平均；
- 五次均向左，仍需单独检查轮胎、轮径、车轮平行度和直线速度匹配；
- 保持相同地面、起点、车头方向和电池状态，再补至少 1–3 次精确脉冲记录。

## 任务 2：按编码器整圈距离回到 A 点

图示赛道中心线一圈长度：

```text
2 × 150 cm + 2 × π × 50 cm = 614.16 cm
按整车平均标定估算：614.16 × 63.56 ≈ 39035 脉冲
```

正式程序不再等待 A 横线，也不再用 IMU 航向作为停车条件。左右轮分别按
`64.45/62.67 脉冲/cm` 换算为实际轮程，取平均达到 `614.16 cm` 后短刹停车；
最后 `30 cm` 保持循迹但将 PWM 等比例降到 `55%`。

执行步骤：

1. [ ] 车体规定参考点准确放在 A，车头沿 A→B；
2. [ ] 车辆完全停车后，测量规定停车参考相对 A 点的有符号偏差；
3. [ ] 统一记录方向：
   - 停在 A 点之前：记为负数；
   - 越过 A 点：记为正数；
4. [ ] 停在 A 点之前，把 `H_TRACK_ENCODER_LAP_STOP_CM_X100` 增大；每差 `1 cm` 加 `100`；
5. [ ] 越过 A 点，把该参数减小；每超 `1 cm` 减 `100`；
6. [ ] 每次只改停车距离，不同时修改循迹 PWM；
7. [ ] 每个候选距离至少重复 `3` 次，最终参数连续测试至少 `5` 次。

### 2026-07-31 首次整圈超程分析

OLED 显示程序是在 `TGT +614.1` 的编码器距离完成态停车，停车航向约
`+460°`；实车比 A 点多走一段 `150 cm` 直线和半径 `50 cm` 的四分之一圆：

```text
超程 = 150 + π × 50 ÷ 2 ≈ 228.54 cm
实际行程 ≈ 614.16 + 228.54 = 842.70 cm
旧程序记录比例 ≈ 614.16 ÷ 842.70 = 72.88%
旧轮询方式约漏记 27.12%
```

检查确认旧 `encoder.c` 依赖主循环轮询 A/B 相；巡线时 OLED 与 IMU 通信会让
采样产生长空档，高速下漏掉正交跳变。现已改为四路 GPIO 双边沿中断计数。
这次不能直接把目标距离改成约 `447.58 cm`，因为它只是在补偿错误的轮询数据；
中断版第一次整圈仍使用真实中心线目标 `614.16 cm`。下一次停车后必须拍到
OLED 的左右编码器页，再根据中断版的 A 点偏差做小范围距离修正。
