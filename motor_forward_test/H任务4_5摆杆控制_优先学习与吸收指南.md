# H 题要求 4、5：摆杆控制优先学习与吸收指南

> 目的：把“AB 预测 + PID + `v²=2ax` + 近端补偿”的想法，收敛为当前 K230 + MSPM0 + X42S + 单摆杆机构可以验证的路线。先完成静车小球闭环，再逐步叠加车辆扰动；不要一次加入预测、积分、弯道和提速。

## 先读这份结论

可以直接吸收的主线是：**位置闭环负责消除残差，车辆运动的已知/可测扰动以前馈方式先抵消，车辆减速和弯道限速负责不让执行器饱和。**

但原方案有四处必须改正，不能照搬：

1. `v² = v0² + 2aΔx` 是恒加速度的运动学关系，**不是**实时加速度测量器。当前车应从双轮编码器速度的滤波差分，或经标定的 IMU 纵向加速度得到 `a_car`；该式可用于规划刹车距离和速度曲线。
2. X42S 的 STEP 脉冲计数只说明 MCU **命令**了多少步，不是白杆实际角度反馈。现有机构无白杆角度编码器，因此不要实现所谓“步进角度 PID 闭环”，更不能据此宣称可检测丢步。
3. 当前相机只发送小球的一个 `x_offset_px`，白杆也只有一个俯仰自由度。它只能控制白杆轴向的一维小球位置。若弯道离心力沿白杆横向，单摆杆无法通过俯仰直接抵消；此时要求 5 的首选措施是**弯道限速和减小转向突变**。只有实测证明离心加速度在白杆控制轴上有投影时，才可以增加该投影的前馈。
4. X42S 目前的接口只有 `STP/DIR/EN`，代码也没有可调电流脚。“接近 ±1 cm 时提高细分电流”目前不可实现；应改成限幅、目标变化率限制、停车/降速和安全回中，除非后续确认驱动器具备可控电流接口。

这也解释了当前工程为何从 **PD** 开始，而不是直接上双环 PID：视觉延迟、白杆角度未测量、机械间隙和摩擦都还没有经过台架辨识。先让简单闭环稳定，才有资格增加模型。

## 当前系统已具备什么

```text
K230 检测钢球 x 坐标
        │ UART3，最新帧 + 校验
        ▼
MSPM0：像素 PD ──► 白杆目标角度(mdeg) ──► 实测角度-POS表 ──► X42S STEP/DIR
        ▲                                                          │
        └────────────── 小球图像位置（唯一的闭环测量）──────────────┘
```

现有控制表达式为：

```text
e_px       = x_target_px - x_ball_px
v_ball_px  = filtered(d(x_ball_px)/dt)
theta_pd   = sign × (Kp × e_px - Kd × v_ball_px)
theta_cmd  = clamp(theta_pd, -2.221°, +1.777°)
POS        = measured_piecewise_map(theta_cmd)
```

角度—POS 表来自白杆实测，允许范围仅为 `−132…+132 POS`。它是唯一允许的转换表，不可用“电机步距角 × 细分”替代，更不可外推。

## 哪些内容吸收，怎样落地

### 1. 先做“PD + 已标定机构”，不要马上加 I

这是当前代码已实现、且最值得先验证的部分。`P` 对位置误差产生倾角，`D` 对小球速度制动。积分只在下列条件都成立后再试验性加入：

- 静车时已经能在中心稳定；
- 完成 `px/cm` 标定，知道 ±1 cm 对应多少像素；
- 视觉帧率、延迟、丢帧率和电机位置跟踪延迟已有日志；
- 加入积分限幅、输出饱和冻结（anti-windup）和“无球/超时清积分”。

若匀速时总是偏向一侧，优先测白杆零位、相机中心和机械摩擦；能用固定零偏或很小的摩擦前馈解决时，不要让 I 项积累后在入弯时放大误差。

### 2. 吸收“前馈优先”，但使用可测的加速度

对于白杆轴与车辆前进方向一致的安装方式，小角度下可把纵向扰动写成：

```text
theta_ff = k_a × a_parallel
theta_cmd = clamp(theta_pd + theta_ff + theta_bias)
```

- `a_parallel`：车辆加速度投影到白杆轴后的值；优先由滤波后的编码器速度差分得到，再以 IMU 交叉核验。
- `k_a`：不要直接固定成 `1/g`。机构倾角、球滚动动力学、相机延迟、安装方向和摩擦都会改变有效系数；从低加速度直线试验辨识其符号和数值。
- `theta_bias`：仅允许经过静车标定后使用的小常量，用于克服白杆自重/零偏。它不是电机“增扭”。

“AB 预测”的可实现版本是根据编码器距离和已知赛段，在起步、预定减速区前平滑改变速度参考；控制器采用这个计划加速度作为前馈。若没有前视相机或可靠赛段定位，不能声称在视觉上提前 0.2–0.3 m识别了弯道。

### 3. 吸收 `v²=2aΔx` 的正确用途：制动规划

在距离终点/标记还剩 `d_brake` 时，以允许减速度 `a_brake` 设定速度上界：

```text
v_limit = sqrt(max(0, 2 × a_brake × d_brake))
```

这能令车轮在到达 B 或 A 前渐进减速，减少小球前冲。`a_brake` 应从编码器实测的可重复刹车曲线取得，并为打滑和控制延迟留余量。它不应由单次 `v²/(2x)` 反推后直接驱动摆杆。

### 4. 将“近端补偿”改为可验证的保护层

这里的“近端”应指接近允许误差边界，而非无依据地提高电机电流。建议逻辑为：

```text
if |ball_error_cm| >= warning_cm:
    降低车速参考；限制转向/制动的跃变；记录一次风险事件
if |ball_error_cm| >= 1.0 cm:
    按比赛与安全策略减速或停车；不能继续盲目加大摆杆角度
```

`warning_cm` 可从 0.6–0.8 cm 起试验。所有阈值必须先由 `pixels_per_cm` 标定得到，不能用未标定像素代替厘米判定。摆杆输出仍受标定的角度、POS、脉冲速率和机械行程四重限制。

### 5. 要求 4：直线 AB（先完成这一项）

建议按“起步—匀速—刹车”三段实施：

1. **起步**：用速度斜坡限制车辆加速度，叠加经过实测的 `theta_ff`；PD 只修正残差。
2. **中段**：计划加速度接近零，保留 PD 和静态偏置；持续记录最大位置误差。
3. **B 前刹车区**：由剩余距离和上式下调 `v_limit`，同一减速度估计自动给出反向前馈；不要在距 B 固定 0.2 m 时突然反转摆杆。

验收顺序：先以低速重复 10 次；确认每次都未越过 ±1 cm，再提高速度。8 s 是上限，不是要求一开始就贴边跑的目标。

### 6. 要求 5：整圈（必须先解决单自由度边界）

路径长度约为 `2 × 1.5 + 2π × 0.5 = 6.142 m`，30 s 的平均速度下限约 0.205 m/s，时间裕量很大。首版不要追高弯速：

- 直道复用要求 4 的纵向前馈与 PD；
- 入弯前按赛段距离主动降速，弯中保持低而平滑的速度，出弯再平滑恢复；
- 记录 IMU 横向加速度、yaw rate、球误差和白杆目标角度，确认弯道是否真是超差源；
- 仅当离心加速度在白杆轴上存在稳定投影，并且方向已实测时，增加 `theta_curve_ff = k_c × a_lateral_projection`。否则该项应为零。

若要求 5 必须同时压制白杆轴向和横向的球偏移，则硬件需要两个独立倾转自由度（或能将球约束为一维的导轨）。一个单侧铰链、一台电机的白杆无法完成二维主动平衡；软件 PID 不能弥补自由度缺失。

## 建议的实施次序与通过门槛

| 阶段 | 只新增/验证的内容 | 通过后才进入下一阶段 |
|---|---|---|
| 0 | K230 UART 电平、协议、ROI、无球安全回中 | OLED稳定显示新鲜帧；断帧≤150 ms必回零且不继续跟踪。 |
| 1 | 静车中心 PD | 在低幅扰动下连续稳定；确认 `BALL_CONTROL_SIGN` 正确。 |
| 2 | 像素—厘米、白杆角度—POS、最大脉冲速率标定 | 能以厘米记录误差，且所有命令都在 `−132…+132 POS` 内。 |
| 3 | 低速直线、车辆速度日志 | 分离车辆加速、匀速、减速三段，找出实际扰动符号与时延。 |
| 4 | 纵向加速度前馈 + 制动速度规划 | AB 多次运行均不超 ±1 cm，再逐步缩短时间。 |
| 5 | 弯道限速 + IMU/误差联合日志 | 一圈先稳定完成，再决定是否存在可辨识的一维弯道前馈。 |

每一阶段都保存：时间戳、`x_ball_px`、换算厘米误差、置信度、车辆左右编码器速度、IMU、`theta_pd/theta_ff/theta_cmd`、目标 POS 与命令/实际脉冲坐标。没有这些数据，PID 参数只能靠猜。

## 暂不做的事项

- 不把 ZIP 内 AnchorBaseDet 代码直接复制到 `k230/steel_ball_uart_yolo.py`；若要换模型，必须另行适配 K230 的模型加载、后处理、ROI 坐标和 `$BALL,...` UART 协议，并重新验证实时帧率。
- 不在尚未静车稳定前接入积分、弯道离心前馈或“误差越大越大力”的增益切换。
- 不因电机为闭环产品就假定当前 MSPM0 能读到其编码器；本工程接口中没有该反馈线。
- 不在无机械限位开关的条件下放宽 `−132…+132` 软件限位。
