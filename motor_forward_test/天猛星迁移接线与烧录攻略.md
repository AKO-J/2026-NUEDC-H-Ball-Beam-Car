# 天猛星 MSPM0G3507 迁移接线与烧录攻略

适用工程：`motor_forward_test`
当前烧录硬件：TI `LP-MSPM0G3507 LaunchPad`（板载 XDS110，序列号 `MG350001`）

> 本文保留为“迁移到天猛星”的接线参考；当前实际烧录和调试使用 LP-MSPM0G3507 的
> 板载 XDS110，**不使用外接 J-Link**。当前工程的通用烧录步骤以
> [README.md](README.md#当前烧录方式lp-mspm0g3507-板载-xds110) 为准。

本文把已验证的 LP-MSPM0G3507 小车工程迁移到天猛星。两者使用同一颗
`MSPM0G3507`，因此本次迁移的原则是：**保持现有 GPIO 名称、保持 32 MHz
时钟和现有控制逻辑，只更换主控板及其接线位置。**

最新功能状态见[智能车_正方形循迹_最新状态.docx](智能车_正方形循迹_最新状态.docx)：
当前完整流程为“灰度角点触发 → 主动刹车 → ICM42688 累计 90° → 低速找回黑线”。

## 1. 先确认硬件方案

本车继续使用原来的外接 TB6612，**不使用天猛星扩展板上的 TB6612**。

1. 扩展板的 U5 TB6612 模块必须不安装或拔掉。
2. 不使用扩展板的 `CN11`、`CN12` 电机接口，也不接该模块的 `VM`。
3. 不使用扩展板预接的 5V MPU6050 接口；ICM42688 按本文的 3.3V 接法单独接线。
4. 若 U5 不能可靠移除或隔离，不叠装扩展板；将外设直接接到天猛星主板标有 GPIO
   名称的排针。

> 禁止将原外接 TB6612 与扩展板 TB6612 并联到同一电机或同一控制信号。电机驱动
> 的 `VM`、USB 5V、主控 3.3V 不是同一电源网络。

## 2. 上电前的总规则

- 所有模块的 `GND`、电机电源负极、天猛星 `GND` 必须共地。
- 天猛星普通 GPIO 只能使用 3.3V 逻辑。禁止任何未经转换的 5V 信号接入 GPIO。
- 编码器已确认使用 **3.3V 供电和 3.3V 逻辑**，四路 A/B 信号可直连。
- Yahboom 灰度模块使用 5V，四根逻辑线必须经过电平转换器。
- ICM42688 全部使用 3.3V；不要接到扩展板的 5V MPU6050 接口。
- 初次通电和所有电机测试均让驱动轮悬空；出现异常立即断开电机 `VM`。

## 3. 当前板载 XDS110 连接与首次下载

将 LP-MSPM0G3507 的调试 USB 直接连接电脑。CCS 应识别为
**LP-MSPM0G3507 LaunchPad (my board)**，调试器为 TI **XDS110 (CMSIS-DAP)**；当前确认的
序列号为 `MG350001`。不需要连接 `CLK`、`DIO`、`RST`，也不需要外接 J-Link。

在 CCS 中选中工程后，依次执行 **Project → Build Project** 和
**Run → Flash Project (<工程名>)**。下载完成且调试会话显示 `Stopped` 时，固件已写入；
若要运行，再执行 **Run → Start Debugging** 或继续该调试会话。

## 4. 外接 TB6612 与电机接线

保持原工程的 A/B 定义：**A 是物理左轮，B 是物理右轮**。

| 原 TB6612 信号 | 天猛星 GPIO / 电源 | 工程含义 |
| --- | --- | --- |
| `PWMA` / `PWM2` | `PB4` | 左轮 A PWM |
| `AIN1` | `PA8` | 左轮方向 1 |
| `AIN2` | `PB26` | 左轮方向 2 |
| `PWMB` / `PWM` | `PB1` | 右轮 B PWM |
| `BIN1` / `SW1` | `PB23` | 右轮方向 1 |
| `BIN2` | `PA25` | 右轮方向 2 |
| `VCC` | `3V3` | 驱动器逻辑供电 |
| `STBY` | `3V3` | 使能；保持高电平 |
| `VM` | 电机电源正极 | 仅电机供电，不能接 USB 5V 或主控 3.3V |
| `GND` | 公共 `GND` | 与主控、电池负极共地 |
| `AO1/AO2` | 物理左电机 | 保持原电机线顺序 |
| `BO1/BO2` | 物理右电机 | 保持原电机线顺序 |

首次测试若某一轮方向与“前进”相反，不要带电交换电机线。先在
`motor_driver.c` 中调整对应的 `MOTOR_A_FORWARD_IN1_HIGH` 或
`MOTOR_B_FORWARD_IN1_HIGH`，再重新构建烧录。

## 5. 双编码器接线（3.3V 直连）

| 编码器信号 | 天猛星 | 说明 |
| --- | --- | --- |
| 左轮编码器 `VCC` | `3V3` | 已确认 3.3V 逻辑 |
| 左轮编码器 `GND` | `GND` | 公共地 |
| 左轮 `E1A` | `PB2` | A 相 |
| 左轮 `E1B` | `PB24` | B 相 |
| 右轮编码器 `VCC` | `3V3` | 已确认 3.3V 逻辑 |
| 右轮编码器 `GND` | `GND` | 公共地 |
| 右轮 `E2A` | `PB9` | A 相 |
| 右轮 `E2B` | `PA27` | B 相 |

`encoder.c` 已将两轮前进统一为正计数，以上四根信号不能交换。若手转时计数方向
异常，先核对电机物理左右和 A/B 相线序，再修改代码中的计数符号；不要盲目交换 GPIO。

## 6. Yahboom 八路灰度模块接线

该模块使用 `AD2/AD1/AD0` 选择 X1–X8 通道，并经 `OUT` 返回一根数字信号，
不是八根独立输出线。

### 6.1 电源与电平转换器

使用四路电平转换器，低压侧 `LV` 接天猛星 `3V3`，高压侧 `HV` 接模块 `5V`；
两侧 `GND` 与主控共地。

| 灰度模块侧 | 电平转换器 | 天猛星 MCU 侧 | 方向 |
| --- | --- | --- | --- |
| `5V` | — | `5V` | 模块供电 |
| `GND` | `GND` | `GND` | 必须共地 |
| `AD0` | `HV1 ↔ LV1` | `PA10` | MCU 输出，地址位 0 |
| `AD1` | `HV2 ↔ LV2` | `PA11` | MCU 输出，地址位 1 |
| `AD2` | `HV3 ↔ LV3` | `PA12` | MCU 输出，地址位 2 |
| `OUT` | `HV4 ↔ LV4` | `PA17` | MCU 输入 |

> 不得把模块 `OUT` 直接接到 `PA17`。先执行地址电压测试，确认 MCU 侧地址高电平
> 约为 3.3V，再连接模块侧。

## 7. ICM42688 接线

| ICM42688P 模块 | 天猛星 | 说明 |
| --- | --- | --- |
| `VCC` | `3V3` | 禁止接 5V |
| `GND` | `GND` | 公共地 |
| `SDA/MOSI` | `PA28` | I2C SDA |
| `SCL/SCLK` | `PA31` | I2C SCL |
| `CS` | `3V3` | 固定 I2C 模式 |
| `AD0/MISO` | `GND` | 通常地址 `0x68` |
| `INT1`、`INT2` | 不接 | 当前固件未使用 |

`PA28` 与 `PA31` 不和当前电机、编码器、灰度接线冲突。I2C 两线不能对调；测试程序会
依次尝试 `0x68` 和 `0x69`。

## 8. 代码与时钟要求

本次迁移不需要改动以下 GPIO 定义：

- `motor_driver.c`：TB6612 的 6 路控制。
- `encoder.c`：4 路编码器输入。
- `gray_sensor.c`：`PA10`、`PA11`、`PA12`、`PA17`。
- `icm42688.c`：`PA28`、`PA31`。

继续使用工程中的 `DL_SYSCTL_SYSOSC_FREQ_BASE` 与 32 MHz 主时钟。软件 PWM 的
`PWM_PERIOD_CYCLES = 32000U` 对应约 1 kHz；不能直接复制天猛星示例的其他时钟配置，
否则全部 `delay_cycles()`、PWM 和采样时间都会改变。

天猛星的用户 LED 为 `PB22`。原 LaunchPad RGB 灯的蓝/绿显示不能作为迁移后的验收
依据；灰度和 IMU 测试以 CCS Watch 中的变量为准。

## 9. 构建、烧录和逐级验收

进入工程目录：

```sh
cd motor_forward_test
```

按下面顺序执行。每完成一步才进入下一步。

| 步骤 | 构建命令 / 操作 | 电机状态 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 断电检查 | 断电 | 无短路；TB6612 `VCC/STBY=3V3`，`VM` 只接电机电源，所有地已共地 |
| 2 | 板载 XDS110 连接 CCS | 断电或 `VM` 断开 | 识别 `LP-MSPM0G3507 LaunchPad (my board)`，无连接错误 |
| 3 | `make gray-address-voltage-test` | 不转 | 依次测 `PA10/PA11/PA12`，选中高电平约 3.3V |
| 4 | `make hand-spin` | 不转，`VM` 可断开 | 手转左右轮时四路编码器边沿和计数变化 |
| 5 | `make icm42688-test` | 不转 | `g_icm42688_who_am_i = 0x47`，`g_icm42688_read_count` 持续增长 |
| 6 | `make right-motor-test` | 悬空 | 右轮 B 通道运行，`g_right_motor_test_encoder_count` 与边沿数大于 0 |
| 7 | `make line-follow` | 悬空后再落地 | 先确认左右轮方向正确，再进入地面循迹 |

各命令生成的 `.out` 文件通过 CCS 的板载 XDS110 下载到目标板。烧录 `line-follow` 后，上电静置约
4 秒完成 ICM42688 零偏标定，期间不要移动小车。

### CCS 烧录

对每个已构建的工程，可以在 CCS 中选中相应项目并执行
**Run → Flash Project (<工程名>)**；板载 XDS110 会擦除并写入目标 Flash。下载完成后，
确认调试会话显示 `Stopped`，再按需要启动运行。

若需要让 AI 或终端快速烧录，工程提供只适用于板载 XDS110 的
`flash_xds110.sh` 及 `targetConfigs/mspm0g3507_xds110.ccxml`。脚本必须显式传入
`--yes`，会擦除、写入和校验，但不会自动启动目标：

```sh
# 构建并烧录默认循迹固件
make flash-line-follow

# 烧录任意已构建镜像
./flash_xds110.sh --yes build/icm42688_test.out
```

开始前确认 LaunchPad USB 已连接、CCS 已显示目标板、且电机 `VM` 已断开或驱动轮悬空。

### 地面验收

先用“直线 + 一个右侧 90° 角”的赛道，不要一开始就跑完整正方形。观察顺序应为：

```text
FOLLOW → BRAKE → TURN → REACQUIRE → FOLLOW
```

CCS Watch 最小观察集合：

| 变量 | 正常表现 |
| --- | --- |
| `g_square_state` | `0 → 1 → 2 → 3 → 0`；`4` 表示故障停车 |
| `g_square_turn_angle_mdeg` | 转弯接近 `90000` 后结束 |
| `g_square_turn_driven_wheel_is_left` | 右侧角为 `1`，左侧角为 `0` |
| `g_line_applied_left_duty` / `g_line_applied_right_duty` | TURN 时符合实际物理转向 |
| `g_square_imu_error` / `g_square_turn_timed_out` | 正常均为 `0` |

首次地面调参只改一项：角度不足或超调先调 `SQUARE_TURN_TARGET_MDEG`；转弯后找不到
黑线先调 `SQUARE_REACQUIRE_DUTY`。完成单角连续 5 次稳定通过后，再测试完整正方形赛道。

## 10. 故障快速定位

| 现象 | 优先检查 |
| --- | --- |
| CCS 未识别板载 XDS110 | 检查 LaunchPad 调试 USB 线是否支持数据、重新插拔 USB；确认 CCS 目标板显示为 LP-MSPM0G3507，而不是选择遗留的 J-Link 配置 |
| 电机不转 | `VM`、电池负极共地、`STBY=3V3`、六根控制线及外接 TB6612 是否被扩展板 U5 干扰 |
| 电机转向相反 | 先确认物理左右和 A/B 电机端；再只改对应 `*_FORWARD_IN1_HIGH` |
| 编码器计数不变 | 编码器 `VCC=3V3`、`E1A/E1B/E2A/E2B` 四线、公共地；先运行 `make hand-spin` |
| 灰度总是 0 或 1 | 检查 LV=3.3V、HV=5V、四路电平转换和 `OUT→PA17`，先执行地址电压测试 |
| IMU 未识别 | `SDA=PA28`、`SCL=PA31`、`CS=3V3`、`AD0=GND`，确认没有接到扩展板 5V MPU6050 接口 |
