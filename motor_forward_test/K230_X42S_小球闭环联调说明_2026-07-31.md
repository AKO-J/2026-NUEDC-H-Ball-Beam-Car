# K230—X42S 白杆小球闭环联调说明（2026-07-31）

## 1. 本版本使用的唯一标定

控制代码只读取 `beam_calibration.c` 中抄录的首版白杆标定点：

| 白杆角度 | X42S POS |
|---:|---:|
| −2.221° | −132 |
| −1.333° | −88 |
| −0.444° | −44 |
| 0° | 0 |
| +0.444° | +44 |
| +1.110° | +88 |
| +1.777° | +132 |

- 这里的角度始终是**白杆角度**，不是 X42S 屏幕显示的电机轴角度。
- 每条控制命令只在相邻两点之间做线性插值，不使用全局“脉冲/度”。
- 超出白杆 −2.221°～+1.777°的控制量先被限制；插值函数本身拒绝外推。
- 电机目标始终限制在 POS −132～+132。

插值例子：

- 白杆 +1.000°：采用（+0.444°，+44）和（+1.110°，+88），插值得 POS 约 +81。
- 白杆 −1.000°：采用（−1.333°，−88）和（−0.444°，−44），插值得 POS 约 −72。
- 当前初始增益下，球位于中心左侧 40 px、速度为零时，请求白杆 +0.320°；采用（0°，0）和（+0.444°，+44），插值得 POS 约 +32。

MSPM0 的 CCS Watch 可直接查看本次实际采用的两点：

- `g_ball_cal_angle_low_mdeg` / `g_ball_cal_angle_high_mdeg`
- `g_ball_cal_pos_low` / `g_ball_cal_pos_high`
- `g_ball_requested_beam_angle_mdeg`
- `g_ball_target_pos`

## 2. 唯一允许的串口接线

当前只用 K230 单向发送，避免占用 X42S 的方向脚：

| 信号 | K230 | MSPM0G3507 |
|---|---|---|
| 视觉数据 | 排针 17，IO5/UART2_TX | 排针 31，PA13/UART3_RX |
| 参考地 | 任一 GND | 任一 GND |

**不要接 PB12。PB12 已用于 X42S DIR。**

断电接线。上电后先用万用表测 K230 IO5 对 K230 GND 的空闲电平：

- 约 3.3 V：可直接接 PA13。
- 约 1.8 V：先加 1.8 V→3.3 V 单向电平转换器，再接 PA13。
- 不得把 5 V 信号接入 PA13。

K230 建议独立稳定 5 V/3 A 供电。USB 5 V 与外部 5 V 不要直接并联；K230、MSPM0 和电机控制信号必须共地。

串口参数为 921600、8 数据位、无校验、1 停止位。数据格式：

```text
$BALL,<valid>,<seq>,<x_offset_px>,<confidence_milli>*<XOR>\r\n
```

`x_offset_px = 球中心 x − 160`，图像右侧为正。XOR 只覆盖 `$` 和 `*` 之间的字符。

## 3. 编译与烧录 MSPM0

```bash
cd motor_forward_test
make ball-beam-vision-control-test
make flash-ball-beam-vision-control-test
```

烧录后先不要按 START。OLED 应显示 `DISARMED` 和 `UART3 WAIT/TIMEOUT`。

## 4. 分阶段硬件联调

### A. 先验证串口，不开摄像头和 YOLO

1. 保持 X42S **DISARMED**。
2. 在 CanMV IDE 运行 `k230/uart_ball_link_test.py`。
3. OLED 应显示 `UART3 RX OK`，`XOFF` 每 0.5 秒循环 −40、0、+40、0。
4. 若一直 `WAIT/TIMEOUT`：
   - 检查 TX 是否确实为 K230 排针 17/IO5；
   - 检查 MSP 接收是否确实为排针 31/PA13；
   - 检查共地；
   - 测 IO5 空闲电平；
   - 检查是否误接了 TX→TX；
   - 不要按 START，也不要先怀疑步进电机。

### B. 验证摄像头和识别

1. 将工程内 `k230/models/yolo11n_det_320.kmodel` 上传并覆盖到 `/sdcard/libs/yolo11n_det_320.kmodel`；模型部署校验值见 `k230/模型部署说明.md`。
2. 在 CanMV IDE 运行 `k230/steel_ball_uart_yolo.py`。
3. 串口日志应先出现 `Camera ready` 和 `Control UART ready`。
4. IDE 图像应为 320×180，并显示红色中心十字和 `X OFFSET`。
5. 将球向图像左右移动，OLED 的 `XOFF` 应同向变化；识别消失时 K230 发送 `valid=0`。
6. 初次联调保持 `ENABLE_WIFI = False`，避免网络连接影响对摄像头、KPU 和 UART 的定位。UART 不依赖 Wi‑Fi。

当前脚本启用了水管 ROI：`x=0..271`、`y=54..101`。IDE 预览会把 ROI 外区域遮黑，且检测框中心落在 ROI 外会被丢弃，不会发给 MSPM0。若水管边缘被切掉，只调整 `PIPE_ROI_X/Y/W/H` 四个常量；保持原始 320×180 坐标，所以控制目标仍是 X=160。

### C. 无球检查白杆方向

1. 取下小球。
2. 用已标定微动程序把白杆调到水平。
3. 在不再移动机构的情况下复位/重新上电 MSPM0，使该物理位置成为软件 POS 0。
4. 再运行完整 K230 程序，确认 UART 和识别均正常。
5. 按一次 START 才会接受人工零点、设置 POS −132～+132 限制并使能电机。
6. 用目标物在画面中制造很小的左右误差，确认：
   - 球/目标在中心左侧时，代码请求正白杆角；
   - 球/目标在中心右侧时，代码请求负白杆角；
   - 实际机构方向若相反，只把
     `BALL_CONTROL_SIGN` 从 `1` 改为 `-1`，不能改标定表的正负号。
7. 再按一次 START 可立即停止并解除使能。

### D. 最后放球

先在中心附近、小误差、低风险状态下放球。至少准备一人随时按 START 停止。确认方向正确后再调增益，不要一开始就让球位于杆端。

## 5. 当前控制策略和可调项

- 目标坐标：`BALL_TARGET_X_PIXEL`，默认 160。
- 初始比例增益：8 mdeg/px。
- 初始微分增益：0.5 mdeg/(px/s)。
- 中心死区：±2 px。
- 视觉置信度下限：0.320。
- 收包超时：150 ms。

视觉无效或超过 150 ms 未收到合法帧时，MSPM0 会命令**已标定的 POS 0**，不会继续保持旧的倾斜角。它仍保持使能，以保持水平位置；按 START 才完全停止并解除使能。

这些增益只是安全的首轮像素域参数。摄像头位置、镜头畸变、球的实际行程和机械摩擦尚未完成物理标定，因此不能把像素误差直接声称为厘米误差。先记录振荡、超调、稳定时间和实际目标误差，再逐步调参。

## 6. 摄像头与机构注意事项

- 摄像头必须固定，白杆在画面里的方向应尽量水平；固定后不要再移动，否则目标 x 与像素比例会改变。
- `set_hmirror(True)` 和 `set_vflip(True)` 会影响图像方向；若改这两项，必须重新验证 `BALL_CONTROL_SIGN`。
- 当前代码选择置信度最高的钢球类别框；环境中出现多个相似高亮圆物体时可能选错。
- 自动启动尚需把验证过的脚本保存为 SD 卡上的 `main.py`；联调阶段先从 CanMV IDE 手动运行。
- 不使用机械限位开关；每次上电都必须执行“无球调水平 → 不动机构 → 复位 → START 接受人工零点”。
- X42S 必须保持 MStep=16，标定表才有效。若微步、连杆孔位、杆长、铰链或电机安装发生变化，必须重新标定。
- OLED 上的 `BEAM mD` 是白杆请求角（毫度），X42S 自带屏幕角度只是电机轴信息，二者不能直接比较。
